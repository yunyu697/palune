# 覆盖/还原类渲染缺陷：独立桌面逐格取证

生成脚本：[layering_evidence.ps1](../../tools/qa/layering_evidence.ps1)
机读结果：[report-hidden.md](report-hidden.md)、[result-hidden.json](result-hidden.json)

## 0. 方法与上一版的关系

上一版跑在**用户交互桌面**上：真 Alt+Tab、真前台按键、22 个副本真启动，全部抢焦点。
方法不合规，**上一版的截图与结论全部作废**，不作为本报告的输入。

当前版本：

- 被测进程、遮挡窗都建在 `CreateDesktop` 出来的独立桌面上（`STARTUPINFO.lpDesktop`），
  用户屏幕上没有任何窗口;
- 不发送真实前台按键序列。按键用 `PostMessage(WM_KEYDOWN/WM_KEYUP)` 定向到 hwnd，
  压窗口用 `SetWindowPos(..., SWP_NOACTIVATE)`;
- 会产生系统错误对话框的启动测试一律在隐藏桌面里做，不落到交互桌面。

## 1. 判据分两层

| 层 | 判据 | 能证明 | 不能证明 |
| --- | --- | --- | --- |
| 结构 | `GetWindow(video, GW_HWNDPREV) == overlay`、两窗可见、矩形回基线 | 双窗分层没被破坏 | 画得对不对 |
| 渲染连续性 | `PrintWindow(PW_RENDERFULLCONTENT)` 取窗口自身像素，扰动前后差异 ≤15% | 窗口自己还在画同一帧 | 屏幕上有没有遮挡残留 |

三个前置门控，缺一就不给「未复现」：

1. **画面静止**：两次取样差异 <0.01。动态画面每帧都在变，差异是内容在动，不是缺陷。
2. **基线可用**：扰动前取样亮度 >3、非全黑像素占比 >0。
3. **呈现证据**：单独起一个运动样片实例（ffmpeg `testsrc2`，30s），连续取 5 次样，
   相邻取样有变化 = 帧确实在被逐帧呈现。没有这条，「差异 0」分不清「画面对」
   与「两边都黑」。

本轮实测：

```
画面静止判定：两次取样差异=0.0000  画面可用=True（亮度 155.2 / 色数 33）
呈现证据：5 次取样相邻变化 3/4 次（该实例亮度 104.0/104.0/104.3/104.9/104.0）
```

## 2. 结果

| 场景 | 判定 | 结构判据 | 渲染连续性（基线 → 结果） |
| --- | --- | --- | --- |
| covered-switchback | 当前构建未复现 | z 序异常 0/3 | 0/3 差异 >15%（最大 0.0000）；155.2/非黑 95% → 155.2/非黑 95% |
| pause-resume | 当前构建未复现 | z 序异常 0/3 | 0/3 差异 >15%（最大 0.0000）；155.2/非黑 95% → 155.2/非黑 95% |
| theme-cycle | 当前构建未复现 | z 序异常 0/3 | 0/3 差异 >15%（最大 0.0000）；155.2/非黑 95% → 155.2/非黑 95% |

这三格的「未复现」由三样东西共同支撑：扰动前后都取到了同一张有内容的画面
（亮度 155.2、非全黑像素 95%）、逐格差异 0.0000、以及上面的呈现证据
（同一个隐藏桌面、同一条抓取链路能取到逐帧推进的画面）。**不是「全黑对全黑」。**

## 3. 未验证的 7 格（单列，不计入通过）

以下各格**不属于通过项**，也不并入任何「全部未复现 / 全部通过」的句式。

| 格 | 状态 | 为什么 |
| --- | --- | --- |
| minimize-restore | 未验证 | 最小化销毁交换链，还原后整窗近全黑（亮度 1.5、非黑 1%）；独立桌面无合成器驱动重绘，取不到可比画面 |
| fullscreen-roundtrip | 未验证 | 全屏重建视频表面，同上 |
| alt-tab-roundtrip | 未在真实前台验证 | Alt+Tab 的语义就是前景切换，独立桌面造不出来；不伪造、不回落用户桌面 |
| covered-by-browser | 未在真实前台验证 | 浏览器遮挡走 DWM 合成层，`PrintWindow` 看不到「谁压在上面」 |
| cross-screen-move | 未验证 | 本机只有 1 台显示器 |
| dpi-change | 未验证 | 无第二台不同 DPI 显示器；注入 `WM_DPICHANGED` 不是真实条件，本轮未注入 |
| sleep-wake | 未验证 | 真休眠会中断整机；注入 `PBT_APMSUSPEND` 不是真实条件，本轮未注入 |

最小化/全屏两格还有一个对照：同一脚本、同一判据换动态样片且不暂停，还原后同样
近全黑、两次取样差异 0.0000，说明隐藏桌面上还原后确实没有新帧被呈现。这是取样
条件问题，**不能写成渲染缺陷，也不能因为「两次都黑、差异 0」算通过**。

## 4. 方法边界（写在这里，后面不再重复试错）

| 缺陷类型 | 隐藏桌面能否验证 | 说明 |
| --- | --- | --- |
| 布局 / 几何 / 命中区（尺寸、位置、对齐、控件高度） | **能** | 纯窗口属性与 `GetWindowRect`，与合成无关 |
| 依赖 / 加载 / 部署（缺 DLL、0xC0000135、Qt 插件初始化） | **能** | 隐藏桌面照样跑加载器，错误框也能在桌面上枚举到 |
| 逻辑 / 状态机（暂停、队列、设置读写、主题切换调用） | **能** | 不依赖呈现 |
| 窗口自身渲染（是否还在画、是否黑屏、是否错帧） | **能，但要有呈现证据** | `PrintWindow` 取的是窗口自己的像素；静止画面必须配呈现探针 |
| 屏幕合成 / 遮挡残留 / 肉眼可见的光晕与白边 | **不能** | 隐藏桌面不参与 DWM 合成，必须真实前台 + 真机截图 |
| 真实 z 序重排（Alt+Tab、前台切换） | **不能** | 语义即前台切换 |
| 跨屏 / DPI 切换 / 休眠唤醒 | **不能**（本机条件） | 需要真实硬件事件，注入是伪造条件 |

结论：**布局、依赖、逻辑走隐藏桌面；合成、z 序、呈现走真实前台。** 不要再拿隐藏
桌面的截图去替代真实前台的结论，也不要为了让数字好看在用户桌面补跑。

## 5. 口径

- 未做修正前代码的 A/B，通过项一律写「当前构建未复现」，**不写「已修复」**。
- 结构判据 15 次采样（5 个可执行场景 × 3 次）z 序异常 0 次，只说明 `enforceLayering`
  的 z 序修复在本构建仍生效，不说明画面正确。
- 屏幕合成层本报告**完全未覆盖**。
